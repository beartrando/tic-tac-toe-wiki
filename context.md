# Работа с проектом

## Структура контекста

* репозиторий **Wiki** — долговременные технические знания проекта. меняется пуллреквестом;
* репозиторий **Context** — рабочий контекст AI-агента. изменяется аи агентом напрямую. при работе над задачей создается от ветки дев.


## Перед началом работы

Перед началом реализации необходимо полностью восстановить контекст проекта.

необходимо изучить:

* Issue и комментарии, если они существуют;

## Анализ задачи

Перед изменением кода необходимо определить:

* что именно требуется изменить;
* какие компоненты затрагиваются;
* какие существующие контракты должны быть сохранены;
* какие контракты или архитектурные решения изменяются;
* какие тесты должны быть добавлены или изменены;
* какие изменения должны быть отражены в Context;

## Реализация

Изменения должны выполняться последовательно и минимально необходимым объёмом и только посредством пр.

Новые решения должны соответствовать существующей архитектуре проекта, если задача явно не требует её изменения.

Если в процессе реализации появляется новое техническое знание, необходимое для дальнейшей работы, оно должно быть отражено в Context.

## Во время работы

Если получена новая информация, имеющая значение для текущего тикета или последующей разработки, она должна быть:

1. отражена в Context, если относится к рабочему контексту;
2. отражена в Issue, если относится к текущей задаче;
3. отражена в Wiki, если имеет долговременное архитектурное или техническое значение.

К такой информации относятся:

* архитектурные решения;
* изменения архитектуры;
* изменения контрактов;
* зависимости между компонентами;
* важные ограничения;
* результаты исследований;
* принятые технические решения;
* обнаруженные особенности существующей реализации;
* решения, которые необходимо учитывать в следующих итерациях.

## Issue

Issue описывает задачу и её текущий рабочий процесс.

Если Issue существует, агент должен поддерживать её актуальность в процессе работы.

Если Issue отсутствует, агент **не должен создавать её самостоятельно**.

Перед завершением работы в существующем Issue необходимо зафиксировать существенные результаты работы.

## пулл реквест

содержит ссылки на все пулл реквесты задачи
содержит ссылку на связные иссуи


## Проверка

Перед завершением работы необходимо:

1. выполнить тесты, относящиеся к изменённому коду;
2. выполнить необходимые интеграционные тесты;
3. выполнить общие проверки проекта, если они предусмотрены;
4. исправить обнаруженные проблемы;
5. повторно выполнить проверки после исправлений.

## Обновление Context

После завершения реализации агент должен проверить Context и привести его в актуальное состояние.

## Связь Issue и PR

**Issue** описывает задачу и её текущий рабочий процесс.

**PR** содержит конкретный набор изменений, реализующий задачу.

PR должен ссылаться на соответствующий Issue, если Issue существует.

## Завершение задачи

Задача считается полностью завершённой только после выполнения всех условий:

* код реализован;
* все прочие инструкции по доставке выполнены
