# Контекст проекта

Контекст проекта хранится в двух связанных источниках:

* **Wiki** — долговременный технический контекст проекта;
* **context/** — контекст, необходимый AI-агенту для работы с кодом.

Репозиторий `context/` является подмодулем проекта и содержит контекст, организованный в соответствии со структурой проекта.

## Wiki

Wiki содержит долговременные знания о проекте, которые должны сохраняться независимо от текущей задачи или состояния реализации.

К Wiki относятся:

* архитектурные решения;
* фундаментальные технические решения;
* общие принципы проекта;
* соглашения и правила разработки;
* описание существенных компонентов;
* обоснование важных решений;
* долговременные ограничения;
* технические решения, которые должны быть доступны при последующей работе над проектом.

Wiki является источником долговременного технического знания проекта.

Изменения Wiki выполняются отдельно и не должны происходить автоматически как побочный эффект реализации обычной задачи.

## Context

`context/` содержит рабочий контекст, необходимый AI-агенту для выполнения задач.

Структура репозитория контекста зеркалит дерево проекта:

```text
context/
├── CONTEXT/
├── proto/
│   └── CONTEXT/
├── services/
│   ├── CONTEXT/
│   └── <service>/
│       └── CONTEXT/
└── ...
```

В `context/` может содержаться:

* текущее состояние реализации;
* актуальные зависимости между компонентами;
* результаты исследований;
* текущие технические решения;
* известные ограничения;
* информация о незавершённой работе;
* результаты предыдущих итераций;
* информация, необходимая для продолжения работы;
* другие сведения, которые необходимы агенту для выполнения текущих и последующих задач.

Context должен содержать **актуальное рабочее состояние**, а не историю изменений.

Устаревшая или опровергнутая информация должна удаляться или актуализироваться.

## Разделение Wiki и Context

Информация должна храниться в том источнике, для которого она предназначена.

**Wiki** используется для долговременного знания проекта.

**Context** используется для рабочего контекста AI-агента.

Одна и та же информация не должна без необходимости независимо дублироваться в Wiki и `context/`.

Если техническое решение имеет долговременное значение для проекта, оно должно быть отражено в Wiki.

Если информация необходима преимущественно для продолжения текущей разработки, она должна находиться в `context/`.

## Актуализация Context

После завершения каждой значимой итерации необходимо проверить соответствующий `CONTEXT`.

В нём должны остаться знания, которые необходимы для продолжения работы следующей итерацией.

Неактуальная информация должна быть удалена или исправлена.

Context не должен превращаться в журнал истории разработки.

## Приоритет источников

При восстановлении контекста использовать следующие источники в порядке приоритета:

1. **Wiki** — долговременные технические решения и знания проекта;
2. **context/** — актуальный рабочий контекст агента;
3. **Issue и комментарии** — требования и текущий рабочий процесс;
4. **код** — фактическая текущая реализация.

Если источники противоречат друг другу, противоречие необходимо обнаружить и разрешить, а не молча выбирать один из вариантов.

Если код отличается от описанного контекста, это должно быть явно установлено как расхождение между документацией и текущей реализацией.

## Источник истины

Для долговременных технических решений источником истины является **Wiki**.

Для рабочего контекста AI-агента источником истины является **context/**.

Код является источником фактического состояния реализации.

Эти источники не должны молча противоречить друг другу. При обнаружении расхождения агент должен сообщить о нём и определить, какой источник необходимо актуализировать.

## Изменение Context

Изменения `context/` выполняются только в репозитории контекста `tic-tac-toe-context` по общему git-workflow, определённому в Wiki.

Рабочий процесс изменения:

1. создать ветку от актуального `dev` репозитория контекста;
2. внести изменения;
3. создать коммит;
4. создать PR в `dev`;
5. выполнить merge только по явному указанию пользователя.

Прямой push в `dev` запрещён.

Прямой коммит в `dev` репозитория контекста запрещён.

## Изменение Wiki

Wiki изменяется по установленному git-workflow.

Изменения Wiki, имеющие архитектурные или долговременные последствия, должны быть осознанными и не должны выполняться агентом автоматически только потому, что они удобны для реализации текущей задачи.

Если реализация задачи приводит к изменению долговременного технического решения, агент должен явно указать на необходимость актуализации Wiki.

## Перед началом работы

Перед началом выполнения задачи агент должен:

1. определить компоненты проекта, которых касается задача;
2. прочитать соответствующий `context/`;
3. прочитать относящиеся к задаче материалы Wiki;
4. изучить Issue и связанные комментарии, если они существуют;
5. проверить текущую реализацию в коде;
6. выявить противоречия между источниками до внесения изменений.

После этого агент может переходить к планированию и реализации задачи.
